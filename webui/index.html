Where do I get the token?

The admin token is the operator credential for the FaultLine control API on this instance. On a fresh FOSS install it is printed by the backend on first boot (look for the FAULTLINE_ADMIN_TOKEN line in the container logs). Set it as an env var on the backend; paste the same value here.

What is the Brain?

The Brain is the LLM backend FaultLine talks to for extraction and recall. It is a model you already run — Ollama, LM Studio, OpenWebUI, or a hosted API. FaultLine does not host one. Point it at host + port (no path); the correct API path is appended from the backend type.

Connect OpenWebUI (recommended path)

The supported path is the OpenAPI tool server — it reliably forwards the per-user identity header FaultLine scopes on. Verified against OpenWebUI v0.10.x; paths apply from v0.6.31+.

  1. Settings → Tools → + (Manage Tool Servers). For an instance-wide server, use Admin Settings → Tools.
  2. URL: http://faultline-mcp:8002 (same Docker network) or http://<host>:8002. If the modal pre-fills https://, change it to http:// for a local server, then hit refresh.
  3. Auth: Bearer → your MCP key (or a per-seat token).
  4. Set ENABLE_FORWARD_USER_INFO_HEADERS=true in OpenWebUI's environment so each user's memory is scoped to them via the X-OpenWebUI-User-Id header. Without it, per-user memory will not work.
  5. OpenWebUI reads /openapi.json and surfaces recall_memory, remember_facts, retract_fact as tools in every conversation.

How memory works

FaultLine stores facts as typed relationships in a structured graph — not summarised text blobs, not document chunks. Every message is scanned for facts worth keeping; facts pass a validation gate before storage, so hallucinated details are rejected at the gate.

Memories strengthen with confirmation; corrections archive the old value cleanly.

You:  "I'm a sysadmin. My main workstation is DevBox, IP 10.0.1.5."

Later:
You:  "What do you know about DevBox?"
AI:   "DevBox is your workstation, IP address 10.0.1.5."
You:  "Actually DevBox moved to 10.0.1.10 after the network change."

Later:
You:  "What's DevBox's IP?"
AI:   "DevBox has IP address 10.0.1.10."
/expand — domain intelligence

Most memory systems store flat facts. /expand teaches FaultLine how a domain works — the structure, the relationships, the vocabulary — so facts about it land correctly and mean something.

/expand networking
/expand kubernetes online https://kubernetes.io/docs/concepts/
/expand tls online https://www.rfc-editor.org/rfc/rfc8446

Without a URL it reasons from training knowledge. With one, it reads the source and builds the ontology from it. Everything /expand builds is still correctable by you — your correction wins.

Corrections & retractions

Corrections update the record cleanly; the old value is archived, not lost. Say "actually, …" or "no, …" and the corrected fact replaces the stale one.

To remove a fact, say "forget X" (naming one subject). The retract_fact tool backs both. Retraction is narrow by design — it targets the one fact you named, never a broad wipe.

Connect a model

FaultLine hooks into an LLM you already run — it does not host one. Point the LLM Brain tab at host + port and pick a backend type. Local servers (Ollama, LM Studio) need no key; hosted APIs (OpenAI, Anthropic, Groq) do.

Your chat client is separate: it talks to the MCP server on :8002. OpenWebUI is wired once with this instance's MCP key (every signed-in user is scoped automatically); a single-user client such as Claude Desktop or opencode uses a per-seat token. See the OpenWebUI tab for the supported wiring.
